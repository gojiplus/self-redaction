\begin{abstract}
Record matching and general PII detection make different errors in a fixed
synthetic corpus. Microsoft Presidio alone fully masks
\AllPresidioMentionRecall{} of labeled mentions. Combining Presidio with fields
from the resolved customer record masks \AllPresidioRecordMentionRecall{}.
Known-mention recall rises from \AllPresidioKnownRecall{} to
\AllPresidioRecordKnownRecall{}, while novel-mention recall remains
\AllPresidioNovelRecall{}. Supplying the wrong customer record removes the
record-matching gain. This is a sanity check, not a performance benchmark. The
result establishes only that record matching and general detection have
complementary error surfaces in these synthetic templates.
\end{abstract}

A service often knows which customer is speaking before it sends a support
conversation to a model, an analytics system, or a log. The resolved record may
contain a name, address, date of birth, order number, and account number. A
redaction service can match selected fields directly and combine those spans
with a general PII detector.

The idea is not new. A 2008 clinical de-identification system matched patient
names from the structured record linked to each note back into the note text. It
combined those matches with dictionaries, regular expressions, and context
rules. Its authors found that a generic spell checker added little sensitivity
and many false positives \citep{neamatullah2008}. A later system created
patient-specific runtime dictionaries and combined them with learned and
rule-based components
\citep{dehghan2015}. Structured patient fields have also been used as the
reference strings for minimum-edit-distance matching in clinical text with
fragments, abbreviations, and misspellings \citep{yuwono2016}. This project
transfers those designs to synthetic customer-support text. It does not claim a
new de-identification method.

\section*{What the check asks}

The check asks whether record matching covers sensitive spans that general PII
detectors miss, without reducing coverage of facts absent from the record. Its
main quantity is full-mention recall: the share of labeled mentions whose
characters are all masked. Results split \emph{known} mentions, whose values
appear in the resolved customer record, from \emph{novel} mentions first
supplied in the chat.

The unit is a labeled mention in a fixed synthetic corpus. The analysis
evaluates every generated chat. No sampling interval is reported because the
corpus does not represent a sampled population of customers or conversations.

\section*{Data and methods}

The generator creates \ProfileCount{} synthetic customer profiles and eight
chats per profile, for \ChatCount{} chats and \MentionCount{} labeled mentions.
It combines fixed lists of 16 first names, 16 last names, 16 street names, four
cities, and four street suffixes by deterministic index rules. It does not
sample real records or estimate a population distribution. Gold spans are
recorded as each chat is assembled rather than recovered by a detector.

Email domains use the reserved example domains. Phone numbers use the North
American 555-0100 through 555-0199 fiction range. Payment-card examples use a
standard test number. Social Security number examples use area numbers 900
through 999, which the Social Security Administration excludes from assignment
\citep{ssaRandomization}.

Four canonical chats per customer use common renderings of known fields. Four
stress chats use a last-name-first name with one deleted or substituted
character, slash-separated phone numbers, hash-prefixed order numbers,
uppercase email, a street line with one character error and no city, state, or
ZIP code, an incomplete date of birth, third-party PII, and ordinary numeric
distractors. The stress suite was written after inspecting the matcher. It is
an adversarial software test, not a held-out sample.

The analysis compares five pipelines:

\begin{itemize}
    \item \emph{Regex} uses the default structured-entity expressions from
    DataFog's \texttt{RegexAnnotator}, pinned to commit \texttt{1dc8cc5}
    \citep{datafog}.
    \item \emph{Record} matches selected fields from the resolved customer
    record. It uses exact field-specific normalization for structured values
    and permits one Levenshtein edit for full names at least seven characters
    long. It also permits one edit in a street name when the house number and
    suffix agree exactly. It does not fuzzy-match numeric identifiers, email
    addresses, phone digits, or dates. It rejects first names, ZIP codes,
    last-four values, and incomplete dates because short values collide with
    ordinary text. RapidFuzz 3.14.5 computes edit distance.
    \item \emph{Regex + record} masks the union of those two outputs.
    \item \emph{Presidio} uses Presidio Analyzer 2.2.364 with its predefined
    recognizers and spaCy's small English pipeline, version 3.8.0,
    \citep{presidio,spacyModel}. The declared entity set covers people,
    locations, dates, email addresses, phone numbers, Social Security numbers,
    payment cards, and IP addresses.
    \item \emph{Presidio + record} masks the union of Presidio and record
    matches.
\end{itemize}

The lock file pins Presidio, spaCy, the English model, and all transitive
dependencies. The Presidio adapter disables live Public Suffix List fetching
and uses the snapshot bundled with the pinned \texttt{tldextract} package. This
keeps email validation independent of network state.

Character metrics ignore entity labels because the immediate task is masking.
Strict entity metrics require the exact boundary and label. The analysis reports
both. A ZIP detector, for example, may mask five sensitive characters inside an
address without finding the full address.

\section*{Results}

Presidio fully masks \AllPresidioMentionRecall{} of mentions across both suites.
Presidio plus record matching masks \AllPresidioRecordMentionRecall{}.
Known-mention recall increases from \AllPresidioKnownRecall{} to
\AllPresidioRecordKnownRecall{}. Novel-mention recall is
\AllPresidioNovelRecall{} for both because the record matcher has no access to
novel facts.

Formatting matters. Record matching covers \CanonicalRecordKnownRecall{} of
known mentions in the canonical suite and \StressRecordKnownRecall{} in the
stress suite. Presidio plus record matching masks
\CanonicalPresidioRecordMentionRecall{} of canonical mentions and
\StressPresidioRecordMentionRecall{} of stress mentions. Record matching covers
every stress-suite known field except the deliberately incomplete date of birth;
Presidio sometimes recognizes that fragment.

\section*{What the result means}

Record matching is strongest where the organization already knows the answer.
It recovers account IDs, order IDs, addresses, and other values that a general
detector must infer. General detection is necessary where the organization does
not know the answer, including new contact details and third-party PII.

The comparison does not establish production accuracy. The same project writes
the profiles, templates, labels, matcher, and stress cases. Presidio is pinned
to one version, one small English model, its default recognizers, and a declared
entity set. A different model, threshold, recognizer configuration, language,
or corpus can produce different results. The regex baseline remains useful as a
transparent floor, not as a competitive detector.

\section*{Production boundary}

A production service should resolve the customer before redaction, preserve the
resolution evidence, and retrieve only fields authorized for matching at the
time of the interaction. Each match should retain its source field, record
version, detector, and normalization rule. Ambiguous or failed resolution
should appear in the result.

Matching should run inside the trusted redaction service. Temporary lookup
values should be discarded after the interaction, and only redacted text should
leave the boundary. Copying the customer record into a model prompt would
defeat the data-minimization purpose of the design \citep{nist800122}.

Record matching cannot find changed contact information, secrets, facts
supplied for the first time, or details about another person. A general detector
and a separate output policy remain necessary. Production monitoring should
measure leaks and over-redaction separately by field type, language, channel,
and resolution state.

\section*{Limits}

The synthetic corpus cannot estimate real-world recall, precision, fairness,
latency, or cost. It covers English text and only one deterministic character
error in selected names and street lines. It omits broader spelling variation,
nicknames, Unicode variation, speech-recognition errors, multi-turn
accumulation, and adversarial evasion. The spaCy small model is a convenient
reproducible baseline, not the strongest available language model.

Masking direct identifiers is not anonymization. Residual text may identify a
person through linked attributes or external information. De-identification is
a family of risk-managed techniques, and some de-identified data can be
re-identified \citep{garfinkel2015}. This check does not measure that risk or
establish legal compliance.

\section*{Reproducibility}

One command generates every profile, chat, gold span, prediction, redacted
output, aggregate CSV file, and TeX input used here. Tests gate corpus counts,
headline results, wrong-record behavior, span scoring, overlap-safe redaction,
conservative matching, Presidio integration, and output completeness. The
repository pins uv 0.12.5 and all Python dependencies in \texttt{uv.lock}.
